# Personas

## A. Product personas (who Verixa serves)

### Sana, QA Engineer (primary)
Reviews every PR, runs UI and API tests, writes Jira tickets by hand.
Pain: retypes errors and screenshot refs across tools.
Wants: know risky PRs fast, one-click runs, evidence in one place, ticket drafted for her.
Must feel in control: nothing reaches Jira without her approval.

### Hamza, Developer
Opens PRs, receives bug tickets.
Pain: vague tickets without evidence or root cause.
Wants: logs, trace and a plain-language cause he can act on.

### Ayesha, QA Lead (mostly FYP-II)
Oversees testers and many PRs.
Pain: no project-wide view of risky modules.
Wants: risk trends, repeat offenders, week-to-week movement.

### Bilal, Startup founder / solo dev
No dedicated tester, little time.
Wants consistent evidence-backed reports with simple setup.

## B. Dev-side personas

### Farheen: Agent Engineer
Applied AI and agentic systems. Thinks in prompts, schemas, retries, evals, guardrails.
Owns orchestration, Manager/Analysis/Report agents, LLM router, DB, redaction.
Ask Claude for: ADK graph design, structured outputs, prompt tuning, eval sets, fallback logic.

### Arisha: QA / Platform Engineer
Software quality assurance. Thinks in coverage, flaky tests, evidence, real tester workflow.
Owns integrations, Test Agent runners, failure classification, evidence pipeline, dashboard.
Ask Claude for: Playwright/Newman runners, test parsing, GitHub/Jira wiring, React screens.

## Using these
- Ask who is working at session start. Follow that person's section.
- Judge UX against Sana: the human stays in control.
